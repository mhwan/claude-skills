# 네이버 대체판 (빅카인즈가 멈췄을 때)

## 차례
- 언제 바꾸나 / 언제 멈추나
- 무엇을 모으고 무엇을 안 모으나
- 검색식 바꾸기
- 매체 고르기
- 얼마나 거슬러 올라가나 (실측)
- 이용 조건 (확인 필요)
- 결과 표시

## 언제 바꾸나 / 언제 멈추나
`scripts/collect_naver.py --evidence "..."` 가 빅카인즈에서 본 글자로 정한다. 막힘 표시가 하나라도 있으면 다른 표시보다 먼저 멈춘다.

| 빅카인즈에서 본 것 | 결과 |
|---|---|
| `HTTP 4xx`(401·403·404·429 등), 로그인, 차단, 캡차, forbidden, too many | 멈춤(exit 1). 우회하지 않는다 |
| 시간 초과, timeout | 네이버로 바꿈 (사유 timeout) |
| 점검, maintenance, 서비스 중단, `HTTP 5xx`, `HTTP 200`(JSON 이 아닌 안내 화면), parsererror | 네이버로 바꿈 (사유 maintenance) |
| `Failed to fetch`, `net::ERR_...`, 연결, connection, `HTTP 0`, `[object Object]` | 네이버로 바꿈 (사유 connection) |
| 그 밖의 것, 빈 글자 | 멈춤(exit 1, 확인 필요) |

- 실제 점검 화면은 아직 본 적이 없다(2026-11-01 기준). 위 표는 `search_bigkinds.js` 의 오류 글자(`describe()` 는 `HTTP n`, 상태 0 은 `[object Object]` 가 됨)를 보고 정했다. 실제 점검 화면 글자는 확인 필요.
- 네이버 쪽 오류(키 오류 401, 권한 403, 하루 한도 429, 연결 실패, 키 없음)는 아무것도 저장하지 않고 멈춘다. 다시 시도하지 않는다.
- 이미 빅카인즈 목록(`raw/list.json` 이 ok·empty)이 있으면 바꾸지 않는다(exit 2).
- `GR_OFFLINE=1` 이면 요청을 보내지 않는다(시험용).

## 무엇을 모으고 무엇을 안 모으나
- 남기는 것: 제목(`<b>` 표시 제거), 원문 링크(`originallink`, 없으면 `link`), 매체, 발행 시각(한국 시각).
- 남기지 않는 것: 발췌(`description`)는 읽지도 않는다. 기사 본문은 가져오지 않는다. 그래서 요약이 없고, `verify_summaries.py` 는 대체판의 요약을 모두 실패시킨다.
- 그 뒤 단계(`normalize.py`, `verify_summaries.py`, `render_report.py`, `purge_raw.py`)는 그대로 쓴다. 본문 단계(6단계)는 건너뛴다.
- 기사 아이디는 `naver-<주소 해시 10자>.<발행 시각>000` 이다.

## 검색식 바꾸기
빅카인즈 검색식을 그대로 넘기지 않고 바꾼다. 바꾼 점은 모두 보고서에 「확인 필요」로 적는다.
- 맨 위의 `OR` 와 `,` 는 검색을 여러 번(최대 10번)으로 나눠 결과를 합친다.
- `AND` 는 지우고 공백으로 둔다. 공백을 네이버가 AND 로 읽는지는 확인 필요.
- `-말`, 따옴표, `|`, 괄호는 그대로 넘긴다. 뜻이 같은지 확인 필요.

## 매체 고르기
- 7개 주요 일간지만 고를 수 있다(`--outlets` 에 다른 이름이 있으면 exit 2).
- 원문 주소의 도메인으로 고른다. `www.`·`m.`·`news.` 만 본사로 보고, `biz.chosun.com` 같은 계열사 주소는 뺀다. 주소가 바뀐 기사는 빠질 수 있다(확인 필요).
- 매체를 고르지 않으면 모두 두고, 7개가 아니면 주소(호스트)를 매체 칸에 적는다.

## 얼마나 거슬러 올라가나 (실측, 2026-11-01, 39회 요청)
네이버는 검색어 하나에 최신순으로 약 1,100건(100건 × 11쪽)까지만 보여 준다.

| 검색어 | 본 기사 | 가장 오래된 날 | 1일 전 | 3일 전 | 7일 전 |
|---|---|---|---|---|---|
| 식품 | 1,100 | 10-30 | 끝까지 | 못 닿음 | 못 닿음 |
| 라면 | 1,100 | 10-26 | 끝까지 | 끝까지 | 못 닿음 |
| 식약처 | 1,100 | 10-27 | 끝까지 | 끝까지 | 못 닿음 |
| 설탕 | 500 | 10-24 | 끝까지 | 끝까지 | 끝까지 |
| 설탕 담합 | 100 | 10-14 | 끝까지 | 끝까지 | 끝까지 |

- 검색별 결과는 「기간 끝까지 확인」·「일부만 확인(잘림)」·「기간에 닿지 못함」 중 하나다. 0건은 「못 찾음」이다.
- 모든 검색이 기간에 닿지 못하고 0건이면 「읽지 못함」으로 보고, 보고서를 만들지 않는다.
- 하루 한도는 25,000회다. 검색 한 번에 최대 11회를 쓴다.

## 이용 조건 (확인 필요)
뉴스·블로그 기사로만 확인했고 공식 약관 원문은 보지 못했다. 시행일도 출처마다 달라 확인 필요.
- 검색 결과는 있는 그대로 보여 주는 데만 쓴다. AI 학습과 결과 요약은 금지라고 알려졌다.
- 임시 보관은 기기 24시간, 서버 21일까지라고 알려졌다.
- 출처 표시와 원문 링크가 필요하다.
그래서 발췌를 남기지 않고, 요약을 하지 않으며, 보고서에 「출처: 네이버 뉴스 검색 API」 를 적는다. 대체판 보고서도 빅카인즈가 돌아오면 다시 모아 바꾼다.

## 결과 표시
- 보고서 첫 줄: `# 뉴스 검색 결과 — 검색어 (기간) · 네이버 대체판 — 본문 미확인`.
- 자료원 줄에 사유, 빅카인즈에서 본 글자(80자까지), 검색별 표, 검색식 확인 필요, 매체 고르기 한계, 「다시 모아야 함」, 「출처: 네이버 뉴스 검색 API」 를 적는다.
- 데이터 파일(gr.envelope/1): `sources` 는 `[{"source": "naver", "status", "requests", "error": "네이버 대체판 — 본문 미확인 (빅카인즈 대체: 사유)"}]`. `warnings` 첫 줄은 대체판 표시, 둘째 줄은 「다시 모아야 함」 이다. 그래서 끝 코드는 3(경고 있음)이다. 행에 `summary` 는 없다.
- 이름이 같은 빅카인즈 보고서를 나중에 만들면 대체판은 `history/` 로 옮겨진다.
