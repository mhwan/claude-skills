## 수집 게이트 7종

`normalize.py` 가 수집 직후 실행한다. 종료코드 1 = FAIL(수집 신뢰 불가).

| # | 게이트 | FAIL 조건 |
|---|---|---|
| 1 | 커버리지 | 성공 매체 / 7 < 0.8 |
| 2 | 매체별 최소 건수 | 평일 5건 · **주말 3건** 미만 (WARN) |
| 3 | 신선도 | 대상일 기사 비율 < 0.9 |
| 4 | 스테일 | 직전 7일 중 **2일 이상**과 헤드라인 세트 완전 동일 |
| 5 | 링크 | 표본(매체당 1건)에 무효 링크 (WARN) |
| 6 | 본문 확보 | **0자** 비율 > 0.1 |
| 7 | 절삭 고지 | FAIL 없음 — 상한 적용 시 반드시 명시(WARN) |

### G4 는 스스로 꺼지지 않는다

비교 이력이 없으면 **PASS 가 아니라 WARN** 이다.
이전 구현은 `days=3` 이라 연휴로 3일 이상 공백이면 "비교 이력 없음(최초 실행)"으로
조용히 PASS 했다. **설·추석 직후가 캐시 고착이 가장 의심스러운 시점인데 바로 그때 꺼졌다.**

지금은 창 7일, 비교한 일수를 항상 문구에 노출하고,
'파일 없음'과 '읽기 실패'를 구분한다(이력 유실을 최초 실행과 혼동하지 않기 위해).

90% 이상 중복도 WARN 으로 잡는다 — 완전 동일이 아니어도 의심스럽다.

### G6 은 두 가지를 구분한다

- **0자** = detailView 실패 → FAIL 기준
- **0자 초과 200자 미만** = 원래 짧은 기사(부음·사진 캡션) → 건수·매체만 표기

섞으면 정상 데이터에 FAIL 이 난다. 실측: 200자 미만 24건 중 20건이
경향신문 뮤지컬 콩쿠르 사진 캡션이었다.

**남은 사각** — 0자가 아닌 오류 텍스트(짧은 접근 제한 안내 등)는 short 버킷에 숨는다.
현재 데이터 496건에서 실현 사례 0건이나 닫힌 것은 아니다.

### G5 는 정직한 UA 를 쓴다

이전 구현은 `Mozilla/5.0` 으로 위장했다. 프로젝트 원칙 위반인 데다 **손해였다** —
매경은 위장 UA 에 403, 정직한 UA 에 200 을 준다.

응답을 `ok` / `blocked`(403·429) / `dead`(404·410) / `error` 로 분해한다.
**차단은 링크가 죽은 게 아니다** — 사용자가 브라우저로 열면 정상이므로 기사를 떨어뜨리면 안 된다.

표본은 무작위 3건이 아니라 **매체당 1건**이다. 한 매체 링크가 통째로 깨져도
무작위 3건에는 안 걸릴 수 있는데, 그게 정확히 이 게이트가 잡아야 할 사고다.

## 근거 게이트

`verify.py {date}`. **이 스킬의 존재 이유 절반이 여기 있다.**

`references/rendering-rules.md` §8 의 lint 10항목은 전부 형식 검사다.
사실성 검사가 하나도 없다. 즉 이 게이트가 없으면
**요약이 원문에 없는 말을 지어내도 전부 통과한다.**

### 검사 항목

| 유형 | 잡는 것 |
|---|---|
| 숫자 | 지어낸 금액·비율·건수 |
| 날짜 | 지어낸 일정 |
| 인용 | 지어낸 발언 |
| 귀속 | 그 이슈에 없는 매체를 든 서술 |
| 모순 | 표에 있는 매체를 「안 썼다」고 서술 · 「N 매체 모두」가 행 수와 불일치 |
| 누락 | 한 줄 요약 빈칸 · 사설 있는데 쟁점 없음 · 축/대상 없음 · 리드 `ref` 없음 |
| 구조 | 논조 행의 `url` 이 의견 기사 목록에 없음 |

### 검사 범위

이슈 요약뿐 아니라 **논조 4블록·축·대상·리드**를 포함한다.
초기 구현은 `rows[].argument` 만 봐서 4블록에 「9999조원 규모라고 보도했다」를 넣어도
통과했다(architect 검증에서 적발).

대조 대상은 **그 항목의 근거로 한정**한다.
- 이슈 요약 → 그 이슈의 기사들
- 논조 논거 → **그 행의 `url` 이 가리키는 글 하나**
- 4블록 → 그 쟁점 행들의 글 합집합
- 리드 → 그 `ref` 가 가리키는 이슈

하루치 전체를 대조 대상으로 삼으면 다른 카테고리 기사에서 우연히 발견된 숫자가 통과한다.
게이트의 목적은 '어딘가에 있음'이 아니라 '이 사안의 근거에 있음'이다.

### 구현상 주의

- **숫자는 토큰 집합으로 비교한다.** 부분 문자열로 찾으면 「150조」가 본문의
  「1500억」 안에서 발견돼 통과한다.
- **집계 표현은 제외한다.** 「6사 9건」「13건」은 요약자가 세어서 쓰는 값이라
  원문에 없는 게 정상이다. 조사가 붙어도 잡아야 한다(「13건으로」).
- **매체명 뒤 조사를 허용하되 복합어는 뺀다.** 「매경이」를 잡되 「중앙은행」은 안 잡는다.
- **부재 주장은 주격 조사를 요구한다.** 「조선 사설에 대한 반론이 없다」에서
  조선은 부재의 주어가 아니라 반론의 대상이다.

## 형식 lint

`verify.py {date} --lint` 는 `references/rendering-rules.md` §8 lint 10항목의 구현체다.
검사 항목은 그쪽을 본다.

## 회귀 테스트

파이프라인을 고치면 **둘 다** 돌린다.

```bash
python3 tests/test_collection_gates.py    # 수집 게이트 8시나리오
python3 tests/test_evidence_gate.py       # 이슈 9케이스 + 논조 6케이스
```

근거 게이트 테스트는 심은 오류 10종을 전부 FAIL 로, 정상 5종을 전부 PASS 로 판정해야 한다.

### 테스트 격리 — 실제 데이터를 건드리지도, 의존하지도 않는다

초기 버전이 `{date}.summary.json` 을 덮어쓰고 마지막에 지워서 **요약본 40건을 날렸다.**
지금은 `TEST_DATE='1999-01-01'` 전용 날짜로 격리한다.

그 다음 버전은 `work/2026-08-21.todo.json` 을 픽스처로 빌려 썼다.
**`prune.py` 를 처음 돌린 순간 테스트가 영구히 안 돌았다.** 정리 대상 파일이었기 때문이다.
본문 전문을 영구 보관하지 않는다는 원칙과도 충돌했다.

지금은 `tests/fixtures/evidence-gate.todo.json` — 케이스가 요구하는 토큰만 담아
직접 지어낸 합성 픽스처다. 파일 상단 `_invariants` 가 케이스와의 계약을 적어둔다
(매경은 이슈에 없어야 하고, 본문에 110·30 은 있고 150·9월 15일 은 없어야 한다).

네트워크 스텁도 실제 함수명(`link_status`)을 잡는지 `assert` 로 확인한다.
이전에는 `link_ok` 라는 옛 이름을 스텁하고 있어서, 격리됐다고 믿은 테스트가
실제로 네트워크를 치고 있었다.
