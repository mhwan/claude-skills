# 요약 작성 계약

`work/{date}.summary.json` 의 스키마와 작성 규칙. `SKILL.md` 4단계의 상세다.

이 파일이 파이프라인에서 **LLM 이 채우는 유일한 지점**이다.
나머지는 전부 스크립트가 결정론적으로 처리한다.

## 스키마

```jsonc
{
  "lead": [
    {"ref": "p2", "text": "**제목** — 한 줄"}
  ],
  "issues": {
    "p1": {"name": "이슈 이름", "oneline": "사실 요약"}
  },
  "tone": {
    "정치": [{
      "issue":  "쟁점 이름",
      "axis":   "판단 축",
      "target": "대상",
      "rows": [
        {"outlet": "조선일보", "kind": "editorial",
         "stance": "비판", "argument": "핵심 논거", "url": "…"}
      ],
      "conflict":  "⚔️ 충돌점",
      "agree":     "🤝 합의점",
      "gap":       "🕳️ 공백",
      "unopposed": "🚫 반론 없음"
    }]
  }
}
```

`work/{date}.todo.json` 이 입력이다. 거기에 각 이슈의 기사 본문(`articles[].body`)과
의견 기사 전문(`opinions[].body`)이 들어 있다. 근거는 그 안에서만 찾는다.

## 작성 규칙

### 분량
| 필드 | 상한 |
|---|---|
| 이슈 `name` | 40자 |
| `oneline` | 90자 |
| `argument` | 120자 |

여러 갈래를 담을 때는 ` / ` 로 구분한다.

### 필수
- **`issues` 는 `todo` 의 모든 `ref` 에 대해 채운다.** 빈칸은 게이트가 잡는다.
- **`lead` 에 `ref` 필수.** 없으면 대조 대상을 특정할 수 없어 FAIL.
  기계가 고른 리드(`todo.lead[].ref`)와 달라도 된다 — 점수는 휴리스틱이지 최종 판단이 아니다.
  다만 `text` 가 실제로 그 이슈를 가리켜야 한다.
- **쟁점마다 `axis`·`target` 필수.** 없으면 렌더링하지 않는다.
- **4블록은 예외 없이 채운다.** 해당 사항이 없으면 `"해당 없음"`.
- **사설이 있는 카테고리는 반드시 쟁점을 세운다.** 칼럼만 있으면 안 세워도 된다.

### 값
- `stance` — `찬성` · `조건부` · `우려` · `비판` · `유보` 다섯 중 하나
- `kind` — `editorial`(사설) / `column`(칼럼)
- `url` — `todo.categories[].opinions[].url` 에서 그대로. 추적 파라미터는 신경 쓰지 않아도 된다
  (검증·렌더 양쪽이 정규화한다)

### 근거
- **숫자·날짜·인용은 원문에 있는 것만.** 게이트가 대조한다.
- 인용부호 안은 **원문 그대로**. 사설 1건당 누적 40자 이내.
  사설 원문이 1,000~1,500자라 요약이 원문 대체재가 되기 쉽다.
- 논거는 **그 매체가 쓴 그 글**에 근거해야 한다. 다른 매체 사설의 내용을 옮기지 않는다.

## 논조 판단 지침

**사설과 칼럼은 층위가 다르다.** 사설은 매체 공식 입장, 칼럼은 개인 필자 서명이다.
렌더러가 사설만 굵게 표시하는 이유다. 칼럼을 사설과 같은 무게로 읽지 않는다.

**아이콘은 같은 축 안에서만 비교 가능하다.** 축이 다르면 색이 같아도 같은 입장이 아니다.
그래서 `axis` 가 필수다.

**한쪽으로 기운 표는 그렇다고 쓴다.** 예를 들어 노동 쟁점에 경영계 시각 사설만 있으면
`gap` 에 "노동 쪽 시각의 사설이 표본에 없다. 이 표는 한쪽으로 기울어 있다"고 적는다.
균형이 없는데 있는 척하지 않는다.

**「미보도」라고 쓰지 않는다.** 매체당 상한 때문에 표본에 안 잡혔을 수 있다.
렌더러가 `⊘ 표본 내 미포착` 줄을 자동으로 붙인다. lint 가 금지어로 검사한다.

## 흔한 실패

실제로 낸 오류들이다. 게이트가 잡지만 애초에 안 내는 편이 낫다.

| 실패 | 예 |
|---|---|
| 매체 귀속 오류 | 현대차 파업 기사를 한경으로 적었다(실제는 중앙). 링크는 맞는데 서술이 틀린 유형 |
| 집계와 표의 불일치 | 「세 매체 모두」라고 썼는데 표에는 2행 |
| 자기모순 | 표에 있는 매체를 `gap` 에서 「쓰지 않았다」고 서술 |
| 리드 ref 어긋남 | 리드 순서를 `todo` 순서로 가정. 실제로 가리키는 이슈로 붙일 것 |
| 원문에 없는 수치 | 어림값을 쓰지 않는다. 원문이 「90조~110조원」이면 그 범위를 쓴다 |

게이트가 못 잡는 것도 있다. **숫자·인용 없이 서술만으로 인과관계를 지어내는 것**은
기계로 검증되지 않는다. 「A 때문에 B가 됐다」는 원문에 그 인과가 없어도 통과한다.
원문을 읽고 쓰는 것 외에 방법이 없다.
